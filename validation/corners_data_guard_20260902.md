# Праг на покритие за корнери — 02.09.2026 (нощна сесия, NOSHT2.md т.1)

## Проблемът

`validation/pokritie_i_byudzhet_20260902.md` (т.1) откри, че `get_models()`
(`match_predictor_app.py`) строеше `corners_model` само ако колоната
`home_corners` **съществува** в `{лига}_merged_full.csv` — без да проверява
дали в нея има реални стойности. За `bulgaria2` колоната съществува, но е
**100% празна** (0 от 1319 завършени мача). `fl.fit_total_model()` прави
`dropna()` → 0 реда → оптимизацията тръгва от нулеви параметри и остава там
(нищо не я движи) → моделът се "фитва" успешно, но предсказва константни
**1.0 корнера на отбор за ВСЕКИ мач**, независимо кои отбори играят.

## Поправката

`match_predictor_app.py` (~ред 251): преди да се фитне `corners_model`, се
смята покритието — сред "завършените" мачове (`home_goals`/`away_goals` не
са празни, същият критерий като `fl.fit_goals_model()`), какъв процент имат
реални стойности едновременно в `home_corners` И `away_corners`:

```python
_finished = df.dropna(subset=["home_goals", "away_goals"])
_corners_coverage = len(_finished.dropna(subset=["home_corners", "away_corners"])) / len(_finished)
corners_model = fl.fit_total_model(...) if _corners_coverage >= CORNERS_MIN_COVERAGE else None
```

Под прага → `None`, точно както `cards_model`/`offsides_model` вече правят
безусловно (25.08.2026) — групата "Корнери ⚠️" просто не се добавя в
`compute_grouped_markets()`, нищо не се логва/показва за нея.

## Прагът: 70%, защо точно това число

Реалните данни (проверени директно, `pandas`, 02.09.2026) образуват два
ясно разделени клъстера:

| Лига | Завършени мачове | Покритие корнери |
|---|---:|---:|
| bulgaria | 1389 | 96.40% |
| england | 1540 | 100.00% |
| england2 | 2269 | 99.47% |
| germany | 1239 | 100.00% |
| germany2 | 1258 | 99.92% |
| spain | 1550 | 99.94% |
| spain2 | 1904 | 99.89% |
| france | 1320 | 100.00% |
| france2 | 1413 | 96.89% |
| italy | 1541 | 99.94% |
| italy2 | 1578 | 99.94% |
| portugal | 1264 | 100.00% |
| champions_league | 1026 | 84.80% |
| europa_league | 921 | 82.30% |
| **conference_league** | 1761 | **69.68%** |
| **portugal2** | 1267 | **47.51%** |
| **bulgaria2** | 1319 | **0.00%** |

13 лиги стоят стабилно ≥96%; `champions_league`/`europa_league` са на
82-85% (граничен, но приемлив случай — солиден обем реални стойности, само
не всеки мач). Долу — три ясни изключения: `bulgaria2` (0%, пълен провал),
`portugal2` (47.5%, под половината реални), `conference_league` (69.68%,
**точно** под кръглия праг от 70%).

**70% е избрано, защото:**
1. Пада точно в празнината между двата клъстера (82.3% най-ниското "добро"
   срещу 69.68% най-високото "лошо") — всяко число между 69.7% и 82.3% дава
   идентичен резултат по трите реални изключения.
2. Кръгло, лесно обяснимо число ("под 70% от завършените мачове нямат
   истински данни за корнери — не строим модел на непълни данни").
3. Съвпада с числото, което самата задача предложи като пример
   ("напр. 70%").

**Честно за граничния случай:** `conference_league` (69.68%) е разлика от
само 0.32 процентни пункта под прага — с праг 65% например би останала
вътре. Решението тук е консервативно (изключва граничния случай), не
защото 69.68% е доказано лошо, а защото няма причина да се предпочете
конкретно число между 65% и 70% пред друго без допълнителен бектест —
70% остава защитимо, кръгло, и в средата на реалната празнина в данните.
Ако занапред `conference_league` събере повече мачове със статистика,
покритието може да мине над прага само по себе си, без промяна в кода.
